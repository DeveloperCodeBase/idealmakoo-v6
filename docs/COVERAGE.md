# نقشهٔ پوشش فرانت‌اند ایده‌آل ماکو

این سند وضعیت **کد موجود** را در برابر [سند اصلی](./ORIGINAL-SPEC.md) ثبت می‌کند. درخواست فعلی مالک، پیاده‌سازی فرانت‌اند با Next.js و TypeScript و آمادگی برای نوشتن بک‌اند است؛ بخش‌های production سمت سرورِ سند اصلی در دامنهٔ تحویل فعلی نیستند. وجود مسیر و دکمهٔ فعال، به‌تنهایی تکمیل تمام قواعد تخصصی آن ماژول را اثبات نمی‌کند.

## ۱. تعریف وضعیت‌ها

| وضعیت | معنی دقیق |
| --- | --- |
| **رابط محلی فعال** | تعامل و تغییر state واقعاً کار می‌کند و در موارد مربوط در مرورگر ذخیره می‌شود. |
| **رابط فعال با دامنهٔ محدود** | مسیر و عملیات پایه موجود است، اما بخش تخصصی مشخص‌شده در ستون باقی‌مانده هنوز پیاده نشده است. |
| **محتوای مستند / حالت خالی صریح** | دادهٔ تأییدشده نمایش داده می‌شود؛ نبود خبر، نماینده، فایل یا دادهٔ فنی با اطلاعات ساختگی پر نشده است. |
| **قرارداد / توسعهٔ آینده** | مدل TypeScript، مرز API یا پیشنهاد معماری وجود دارد؛ سرویس عملیاتی ساخته نشده است. |

حالت `NEXT_PUBLIC_DATA_MODE=api` فقط ایجاد درخواست را به `POST /requests` وصل می‌کند. فهرست/ویرایش درخواست، CMS، CRM، ورود و انتشار همچنان محلی‌اند. جزئیات قطعی اتصال در [BACKEND-CONTRACT.md](./BACKEND-CONTRACT.md) آمده است.

## ۳. پوشش مسیرهای عمومی سند اصلی

در جدول زیر، همهٔ مسیرها بعد از `/{locale}` هستند. لیست قطعی قابل ساخت در `src/lib/routes.ts` تعریف شده است. جزئیات محصولات، پژوهش‌ها، اسناد و صفحات شرکتیِ شناخته‌شده slug ثابت دارند؛ برای محتوای تازهٔ محلی از `detail` یا `page` همراه query استفاده می‌شود.

### ۵.۱. ۲۸ بلوک موجود

هر نوع در palette با عنوان پنج‌زبانه وجود دارد. بلوک‌ها ساختار مشترک `{id,type,title,body,mediaUrl?,link?,formId?,formSchema?,hidden?,options?}` دارند؛ preview هر نوع در `CMS.tsx` رسم می‌شود. برای بلوک فرمِ متصل، `formSchema` نسخهٔ بازبینی‌شدهٔ تعریف فرم است؛ پاسخ‌های خصوصی وارد انتشار عمومی نمی‌شوند و تغییر بعدی فرم، snapshot مصوب صفحه را بی‌صدا عوض نمی‌کند.

| گروه | نوع‌های موجود |
| --- | --- |
| معرفی و متن | `hero`, `rich-text`, `split`, `cta`, `notice`, `divider` |
| محصول و اسناد | `product-carousel`, `catalog-carousel`, `news-carousel`, `product-grid`, `features`, `specifications`, `downloads` |
| رسانه | `image`, `gallery`, `video`, `audio` |
| محتوای سازمانی | `faq`, `timeline`, `statistics`, `certificates`, `team`, `testimonials`, `partners` |
| تماس و تعامل | `contact`, `map`, `form`, `tabs` |

نوع بلوک‌های موجود، تضمین مدل تایپ‌شدهٔ اختصاصی و editor تمام ویژگی‌های هر بلوک نیست. برخی داده‌ها از متن خطی یا `label|value` خوانده می‌شوند. شمارنده/گواهی/تجربهٔ مشتری در یک بلوک تحریریه، خودبه‌خود به دادهٔ مستند کارخانه تبدیل نمی‌شود. هر ۲۸ نوع در editor preview و renderer عمومی `PublicationRenderer.tsx` پشتیبانی می‌شوند؛ ویژگی‌های تو‌در‌تو و طراحی آزادتر هر نوع به توسعهٔ بعدی editor مربوط است.


### ۵.۲. مجوزهای قابل اجرا و دادهٔ هر نقش

`src/lib/auth.ts` سیاست مرکزی و `workspace/permissions.ts` مرز فرمان محلی‌اند. URL ناشناخته و زیرمسیر دلخواه دسترسی نمی‌گیرند. سایدبار و جستجوی سریع فقط مسیر/رکورد مجاز را می‌سازند؛ گزارش تحلیلگر صرفاً عدد است. دادهٔ استخدام از ناشر و فروش پنهان می‌شود؛ نام، تماس و شناسهٔ درخواست کیفیت برای بازبین علمی حذف می‌شوند و یادداشت علمی دادهٔ اصلی را تخریب نمی‌کند. پیش‌نمایش فرم، پاسخ واقعی تولید نمی‌کند؛ پاسخ‌های فرم فقط به نقش دارای مجوز پاسخ نمایش داده می‌شوند. این‌ها مجوز رابط و state محلی هستند، نه حفاظت چندکاربرهٔ سرور.

ورود کارکنان به `/{locale}/admin/` پیشخوان اختصاصی همان نقش را باز می‌کند. اقدام اصلی هر نقش به ماژول کاری متفاوت می‌رود؛ customer فقط پورتال خودش را دارد. جدول دقیق نقش‌ها در `BACKEND-CONTRACT.md` آمده است.

## ۷. مرکز پایش؛ تمام ۱۲ گروه مسیر

همهٔ مسیرهای زیر در `/{locale}/admin/monitoring` موجودند و از یک shell پایش، تب‌ها، شمارنده‌های محلی، تاریخچه، registry سرویس‌ها و اطلاعات storage استفاده می‌کنند. ظاهرِ مسیر تخصصی به معنی اتصال telemetry تخصصی آن نیست.

## ۹. مرز آزمون و پذیرش

آزمون‌های `tests/workspace-permissions.test.mjs` و `tests/site-content-control.test.mjs` برای مجوز مسیر/فرمان، تفکیک state، منع خودتأییدی، انتشار snapshot و مهاجرت خانه افزوده شده‌اند. آزمون‌های `tests/account.test.mjs`، `catalog.test.mjs`، `frontend-state.test.mjs` و `workspace.test.mjs` قرارداد داده، پاک‌سازی state، مالکیت/پیام عمومی، CSV اقلام، مسیریابی درخواست، جلوگیری از تکرار و پاسخ پیشنهاد بدون برد خودکار فرصت را بررسی می‌کنند. `crm-tools.test.mjs` محاسبات دقیق، ارز/قیمت نامعلوم، ورود CSV و بازگردانی ادغام با حفظ دادهٔ جدید را پوشش می‌دهد؛ `product-editor.test.mjs` و `product-release.test.mjs` قرارداد محصول و snapshot منتشرشده را بررسی می‌کنند. `site-preferences.test.mjs`، `form-schema.test.mjs` و `pwa-policy.test.mjs` به‌ترتیب تنظیمات عمومی، شروط/نسخهٔ فرم و allowlist کش را بررسی می‌کنند. typecheck مرزهای TypeScript را بررسی می‌کند؛ شمار نهایی آزمون/مسیر از گزارش verifier و README تحویل خوانده شود.

این آزمون‌ها جای اجرای سناریو در مرورگر واقعی، بررسی بصری RTL/LTR و dark/light، کار با screen reader، لمس/drag در موبایل، آزمون persistence محدود مرورگر، یا آزمون همزمانی چند کاربر با سرور را نمی‌گیرند. در این محیط، ابزار مجاز مرورگر برای QA در دسترس نبوده و نتیجهٔ تست تصویری یا end-to-end مرورگری ادعا نشده است. نتیجهٔ build و فرمان‌های اجرا در README تحویل ثبت می‌شود.

برای ادامهٔ پروژه، سه کار مستقل باقی می‌ماند: تکمیل editorها و گردش‌های تخصصی علامت‌خورده در همین سند، اجرای پذیرش رابط روی مرورگرهای هدف، و ساخت/اتصال بک‌اند بر اساس [BACKEND-CONTRACT.md](./BACKEND-CONTRACT.md). این تفکیک باعث می‌شود فعال‌بودن UI محلی با آماده‌بودن سامانهٔ تولیدی اشتباه نشود.
